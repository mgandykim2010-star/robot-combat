# ROBOT BATTLE — 온라인 멀티플레이 서버

이 저장소의 기존 게임 클라이언트는 GitHub Pages에서 제공하고, 실시간 방/전투 중계는 Node.js + Socket.IO 서버가 담당합니다.

## Render 배포

1. Render 계정에 로그인하고 **New → Blueprint**를 선택합니다.
2. GitHub 저장소 `mgandykim2010-star/robot-combat`를 연결합니다.
3. 배포할 브랜치로 `online-multiplayer`를 선택합니다.
4. 저장소 루트의 `render.yaml`을 Blueprint 설정으로 사용해 서비스를 생성합니다.
5. 배포가 끝나면 서비스의 **Settings**에서 `https://...` 형태의 공개 URL을 복사합니다.
6. `index.html`의 `RB_SERVER_URL` 값을 그 주소로 바꾸고 커밋합니다.
7. 온라인 게임을 GitHub Pages에 공개하려면 이 브랜치의 변경 사항을 `main`에 병합합니다.

서버 상태 확인: `https://서비스주소/health` 에서 `{"status":"ok"}`가 반환되어야 합니다.

## 동작 구조

- 방 코드는 영문/숫자 6자리이며, 한 방 최대 10명입니다.
- 최초 입장자가 방장이 됩니다. 방장이 나가면 남은 참가자 중 한 명에게 방장 권한이 이전됩니다.
- 방장은 전투 시작 이벤트와 전투 상태 브로드캐스트를 담당합니다.
- 클라이언트는 플레이어 입력을 presence로 보내고, 방장은 기존 게임 로직으로 전투를 계산해 상태를 중계합니다.
- 팀 전투는 기존 로직대로 블루 5명 / 레드 5명으로 구성하며 빈자리는 AI가 채웁니다.

## 중요한 제한

- Render 무료 인스턴스는 일정 시간 요청이 없으면 잠들 수 있어 첫 접속에 지연이 생길 수 있습니다.
- 이 서버는 현재 메모리 기반 방 관리입니다. 서버 재시작/절전 후에는 진행 중인 방이 초기화됩니다.
- 이 단계는 기존 클라이언트 로직을 유지한 실시간 중계 MVP입니다. 랭킹/계정 데이터는 기존처럼 각 브라우저의 localStorage에 저장되며 서버 간 공유되지 않습니다.
- 공개 서비스로 확대하기 전에는 계정 인증, 서버 측 입력 검증/속도 제한, 전투 결과 검증, 재접속 복구를 추가해야 합니다.
